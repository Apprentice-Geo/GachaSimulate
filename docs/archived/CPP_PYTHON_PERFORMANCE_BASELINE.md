# C++ / Python 模拟—统计链路性能基线

> 本报告已归档，后续应避免修改，只作为开发历史记录

## 结论

本报告比较提交 `71afa7d975de035c4fa89d8c288b7df5f1c4c605`（`feat: compelete phase 4`）上的 C++ 与 Python 链路。实验开始前工作区为空，C++ Release 产物已由当前源码构建并安装。

- 在更能代表持续负载的 `1,000,000 runs` 下，C++ 的“模拟→保存”串行耗时为 Python 的约 `1/9.99` 至 `1/10.60`，16 并发耗时为约 `1/11.33` 至 `1/15.67`。
- 同规模“模拟→统计→保存”中，C++ 串行快 `9.78–10.34×`，16 并发快 `10.47–12.18×`。
- `1,000,000 runs` 串行峰值聚合 RSS：C++ 为 `30.3–33.6 MiB`，Python 为 `502.2–617.2 MiB`；16 并发时 C++ 为 `30.5–33.9 MiB`，Python 为 `944.3–1029.5 MiB`。
- Python 的 16 进程方案在 `100` 和 `10,000 runs` 下主要消耗在进程与 IPC 编排，通常比 Python 串行更慢；C++ 16 线程在 `10,000 runs` 已开始受益，在 `1,000,000 runs` 达到约 `4.62–6.52×` 的链路加速。
- `100 runs` 的 C++ 样本只有数毫秒，容易受调度抖动影响；该档只用于观察启动成本，不应用于推导稳定吞吐。

## 实验边界

测量固定 runs、`draw` 指标以及两种链路：

1. **模拟→保存**
   - C++：启动 `gachasimulate-core`，加载已编译 IR，模拟并写入 `.gsr`。
   - Python：启动 Python，加载 YAML 并构建运行时上下文，模拟并写入 `.npz`。
2. **模拟→统计→保存**
   - C++：完成上述链路后，另行启动 `gachasimulate-analyze`，读取 `.gsr` 并把 Analysis v1 JSON 写入文件。
   - Python：在同一 Python 进程内完成模拟和 `.npz` 保存，再计算统计并写入 `_visualize.json` 等价内容。

计时使用外部 wall clock，包含原实现的进程启动、模块加载、运行时配置加载、并发 worker/thread 创建、模拟、统计和文件写入。C++ 的 YAML→IR 编译位于模拟链路上游，在计时前完成；Python 当前没有独立 IR，因此其 YAML 校验与运行时构建包含在计时内。这是当前两种实现边界的真实差异，不是纯算法微基准。

Python 受 GIL 约束时使用现有多进程实现；Manager、IPC、worker 启动与回收都是该实现的组成部分，本报告不扣除或单独摊销这些成本。所有时间均从链路进程启动统计到最后一个链路进程结束。

C++ 与 Python 保存格式及统计 JSON schema 不同，因此本实验比较的是当前可交付链路的时间和内存成本，不比较相同编码器的性能。每次试验都检查结果文件非空；统计链路额外解析 JSON 并确认存在 `statistic`。

## 实验设计

- Case：`baseline_probability`、`condition_tree_rules`、`weighted_pool`，分别覆盖基础概率、条件树规则和加权池。
- 规模：`100`、`10,000`、`1,000,000 runs`。
- 并发：两侧均使用 `1` 和 `16` 个 worker/thread。
- 随机种子：`123`。
- 独立重复：三个规模分别为 `7`、`5`、`3` 次，表中取中位数。
- 顺序：以固定种子随机打散全部 360 个试验，避免实现或规模与机器状态变化系统性重合。
- 时间：`time.perf_counter()` 包围完整子进程链路。
- 内存：每 `1 ms` 从 `/proc` 汇总进程树 RSS，并以 GNU `time` 的单命令最大 RSS 补足毫秒级短进程；表中取峰值聚合 RSS 的中位数。
- 临时 IR、GSR、NPZ 和 JSON 均在单次试验后删除；测量脚本仅临时使用，不进入产品代码或仓库。

“峰值聚合 RSS”会把多个进程共享页面分别计入各进程 RSS，因此代表多进程驻留内存上界，不等同于 PSS 或机器物理内存净增量；它适合观察 Python 16 进程方案的规模，但不应解读为精确的独占内存。

## 限制

- 机器未做 CPU pinning、关睿频或后台服务隔离；随机交错和重复中位数用于降低这些影响。
- 写入目标是 WSL2 的 Linux 文件系统临时目录；结果不代表 Windows 文件系统挂载路径或机械硬盘。
- 聚合 RSS 不是 PSS。若后续需要制定严格的容器内存 limit，应在目标部署环境使用 cgroup `memory.peak` 复测。
